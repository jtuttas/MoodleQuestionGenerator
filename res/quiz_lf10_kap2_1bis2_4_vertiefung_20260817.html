Frage 2 L2-K21 Binaer 00101010 nach Dezimal Berechnung 1 Pt.

Der Lichtpult-Rechner einer Buehne hat das letzte IP-Oktett in Binaerdarstellung: 00101010.

Loesung:

00101010: Bit 5 (32) + Bit 3 (8) + Bit 1 (2) = 32 + 8 + 2 = 42. Pruefen: 42 dezimal = 00101010 binaer. Korrekt!

Ein Techniker prueft, wie viele verschiedene Werte ein einzelnes Byte (8 Bit) darstellen kann. Die Formel lautet 2^Anzahl_der_Bits.

Loesung:

Frage 5 L2-K21 Nibble Hex Zuordnung Zuordnung 4 Pt.

Loesung:

Frage 7 M1-K21 Subtraktionsverfahren 172 Schritte Reihenfolge 1 Pt.

Um das erste Oktett (172) der IP-Adresse 172.16.0.1 in Binaer umzurechnen, wird das Subtraktionsverfahren angewandt. Bringen Sie die Schritte in die richtige Reihenfolge.

Klicken Sie die Elemente in der richtigen Reihenfolge an.

  • 8 passt: Bit=1, Rest=4

Frage 10 L2-K22 Nutzbare Hosts 27er Subnetz Berechnung 1 Pt.

Fuer die Buehnenverkabelung einer Produktionsmesse planen Sie ein /27-Subnetz.

Rechenweg: /27 hat 5 Hostbits, 2^5=32 Adressen, minus 2 reservierte. Wie viele nutzbare Hostadressen hat ein /27-Subnetz?

Loesung:

/27: 5 Hostbits. 25 = 32 Adressen. 32 - 2 = 30 nutzbare Hosts. Abgezogen werden Netzadresse (alle Hostbits=0) und Broadcast (alle Hostbits=1).

Frage 20 M1-K23 Fragmentierung 3200 Byte bei MTU 1500 Berechnung 1 Pt.

Ein Netzwerk-Video-Frame hat 3200 Byte Payload. MTU im Netz: 1500 Byte. IP-Header: 20 Byte.

Nutzbare Payload pro Fragment = 1480 Byte. Fragmente = ceil(3200 / 1480) = ?

Loesung:

Fragment 1: Byte 0-1479 (1480 B). Fragment 2: Byte 1480-2959 (1480 B). Fragment 3: Byte 2960-3199 (240 B). Gesamt: 3 Fragmente. ceil(3200/1480) = ceil(2,162) = 3.

Frage 21 M2-K23 TCP UDP Anwendungszuordnung Zuordnung 5 Pt.

Beim Aufbau des Konzertnetzwerks waehlen Sie fuer jede Anwendung das richtige Transportprotokoll. Ordnen Sie zu.

BegriffZuordnung
Netzwerk-Audio-Uebertragung (Echtzeit, 48 kHz)
Konfigurationsdaten auf Switch hochladen
Netzwerk-Video-Stream (Live-Kamera)
Webinterface eines Medienservers aufrufen
Lichtsteuerung ueber IP (Live-Buehne)
Loesung:

UDP: Netzwerk-Audio, Netzwerk-Video, Lichtsteuerung ueber IP - alle zeitkritisch, Latenz wichtiger als Vollstaendigkeit. TCP: Konfigurationsdaten, Datei-Upload, Webinterface - Datenvollstaendigkeit entscheidend, keine Latenz-Prioritaet.

Frage 22 M3-K23 TCP Three-Way-Handshake Reihenfolge Reihenfolge 1 Pt.

Die Konfiguration eines IP-Lichtpults wird per TCP uebertragen. Bringen Sie die Schritte des TCP-Verbindungsaufbaus (Three-Way-Handshake) in die richtige Reihenfolge.

Klicken Sie die Elemente in der richtigen Reihenfolge an.

  • Client sendet SYN (Verbindungsanfrage)
  • Datenuebertragung (bidirektional)
  • Verbindungsabbau per FIN/ACK-Austausch
  • Server antwortet mit SYN-ACK
  • Client sendet ACK (Bestaetigung)
Loesung:

Three-Way-Handshake: 1. Client → SYN. 2. Server → SYN-ACK. 3. Client → ACK. 4. Datenuebertragung. 5. Verbindungsabbau per FIN/ACK. UDP hat keinen Handshake - daher schneller, aber ohne Garantie.

Frage 23 S1-K23 Fragment Offset letztes Fragment Berechnung 1 Pt.

Ein 4000-Byte-IP-Paket (nur Payload, ohne Header) wird bei MTU 1500 Byte fragmentiert (IP-Header: 20 Byte, nutzbare Payload pro Fragment: 1480 Byte).

Fragment 1: Byte 0-1479. Fragment Offset = 0/8 = 0.
Fragment 2: Byte 1480-2959. Fragment Offset = 1480/8 = 185.
Fragment 3: Byte 2960-3999. Fragment Offset = 2960/8 = ?

Welchen Wert hat der Fragment Offset des dritten (letzten) Fragments?

Loesung:

Letztes Fragment beginnt bei Byte 2960 der Payload. Offset-Einheit: 8 Byte. Fragment Offset = 2960 / 8 = 370. Fragment 3 traegt Byte 2960-3999 (1040 Byte Payload).

Loesung:

Loesung:
